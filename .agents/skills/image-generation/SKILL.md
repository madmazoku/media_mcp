# Скилл генерации изображений (media_mcp)

## Основной принцип: Модель первична, LoRA вторична
1. **Никогда не подбирать и не переключать модель чекпоинта под LoRA.**
2. Активная модель определяет архитектуру (`SD 1.5`, `SDXL`, `Pony`, `FLUX.1`, `FLUX.2 Klein`).
3. **LoRA всегда выбирается строго под текущую модель, а не наоборот.**
4. LoRA для FLUX.1 **категорически запрещено** подключать к FLUX.2 Klein (несовпадение скрытых размерностей 4096 vs 3072).

---

## Доступные инструменты (Tools):
- **`image_generate`** (`schemas/requests/image_generate.json`): единый инструмент генерации изображений:
  - `prompt` *(string, опционален при наличии `image_path`)*: текстовое описание сцены. Если `image_path` указан без `prompt` и `mask_path` при `fit="crop"`, выполняется пассивная подгонка разрешения без запуска диффузии.
  - `engine` *(`"sdxl"` | `"flux1"` | `"flux2"`, по умолчанию `"sdxl"`)*.
  - `model` *(string, опционально)*: имя файла модели/чекпоинта.
  - `width`, `height` *(int, кратны 16)*.
  - `steps` *(int)*, `seed` *(int)*.
  - `cfg` *(number, для SDXL; для Pony автоматически подставляется 5.5)*.
  - `guidance` *(number, для FLUX.1/FLUX.2)*.
  - `sampler` *(string, опционально)*.
  - `loras` *(array of `{"name": str, "strength": float}`, опционально)*: поддержка цепочки нескольких LoRA.
  - `negative_prompt` *(string, SDXL only)*.
  - `image_path` *(string, опционально)*: путь к существующему изображению на диске для перерисовки (img2img). При указании без `fit` параметры `width` и `height` запрещены — движок автоматически рассчитывает оптимальное нативное разрешение модели (~1.0 MP) с точным сохранением пропорций исходного изображения.
  - `fit` *(`"crop"` | `"outpaint"`, опционально)*: стратегия подгонки изображения при явном указании целевых `width` и `height` вместе с `image_path`:
    - `"crop"`: масштабирует изображение с сохранением пропорций до полного покрытия целевого кадра и центрирует обрезку (center crop).
    - `"outpaint"`: масштабирует изображение до вписывания в целевой кадр, дополняет недостающие поля холста краевой подложкой и автоматически генерирует плавную маску инпейнтинга со сглаженным переходом (Gaussian blur) для генерации новых областей окружения.
  - `mask_path` *(string, опционально)*: путь к изображению маски для локального редактирования (inpainting). Разрешён строго при наличии `image_path`. Белый цвет (255) — перерисовать, чёрный (0) — сохранить. Поддерживает непрерывные полутона (градиенты и мягкие кисти 0..255) для бесшовного смешивания и контролируемой степени изменений без бинаризации. При `fit="outpaint"` автоматически объединяется с маской полей.
  - `denoise` *(number, 0.05..1.0, по умолчанию 0.65)*: сила перерисовки исходника для img2img/inpaint (0.05 — лёгкая стилизация, 0.65 — сбалансированная трансформация, 1.0 — полная перерисовка). Разрешён только при наличии `image_path`.
  - **Автоматическое сохранение спецификации:** каждый запуск сохраняет итоговый разрешённый JSON-спецификатор в `workflows/{run_prefix}-spec.json` и возвращает `run_prefix` и `spec_path` в ответе.
  - **Автономный CLI запуск:** `cmd\cli.cmd [--config config.json] image_generate [request_file | -]`.
  - **Автоматическое повышение разрешения для SDXL/Pony:** при запросе невысокого разрешения (< 0.75 МП, например, 832x480) движок автоматически рендерит в полноценном высоком разрешении (1280x720), предотвращая деградацию внимания SDXL и деформацию анатомии.
- **`media_get_models`** (`schemas/requests/media_get_models.json`): инспекция моделей чекпоинтов с фильтром `type="image"`.
- **`media_get_samplers`** (`schemas/requests/media_get_samplers.json`): список совместимых сэмплеров для конкретного `engine` и `model`.
- **`media_get_loras`** (`schemas/requests/media_get_loras.json`): список совместимых LoRA с извлечёнными триггерными словами. Поддерживает опциональный `pattern` (регистронезависимый Python regex для фильтрации по имени LoRA и её триггерам, например `'hermione|emma'`, `'cyber.*'`, `'bikini'`).

## Отображение в чате
- Инструмент возвращает компактный структурированный JSON с полем `image_path` (абсолютный путь к сохранённому файлу `.png`).
- Выводить полученное изображение в чат через markdown:
  ```markdown
  ![Описание](file:///path/to/image_path)
  ```
  *(Если среда клиента требует размещения файла в сессионном каталоге артефактов для отрисовки в UI, скопировать файл в каталог артефактов сессии и сослаться на него).*
- Ниже давать кликабельную ссылку на оригинальный файл изображения и спек `{run_prefix}-spec.json`.

## Запрет на самопроверку
- **Категорически запрещено** вызывать `view_file` или анализировать сгенерированные картинки без явного запроса пользователя. Сразу отдавать результат генерации в ответ.
