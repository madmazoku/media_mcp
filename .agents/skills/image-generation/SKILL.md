# Скилл генерации изображений (media_mcp)

## Основной принцип: Модель первична, LoRA вторична
1. **Никогда не подбирать и не переключать модель чекпоинта под LoRA.**
2. Активная модель определяет архитектуру (`SD 1.5`, `SDXL`, `Pony`, `FLUX.1`, `FLUX.2 Klein`).
3. **LoRA всегда выбирается строго под текущую модель, а не наоборот.**
4. LoRA для FLUX.1 **категорически запрещено** подключать к FLUX.2 Klein (несовпадение скрытых размерностей 4096 vs 3072).

---

## Доступные инструменты (Tools):
- `comfy_flux_txt2img`: генерация через FLUX.1 Dev или FLUX.2 Klein в ComfyUI.
- `sd_txt2img`: генерация через A1111 (SDXL, Pony, Illustrious, SD 1.5).
- `sd_get_models` / `sd_set_model`: получение списка и смена модели в A1111.
- `sd_get_loras`: получение списка LoRA.
- `sd_interrupt`: отмена генерации.

---

## Отображение в чате
- При вызове MCP сервер возвращает изображение в формате `{"type": "image", "data": "..."}`.
- Клиент автоматически кэширует его в локальный offload (`[Resource offloaded to file:///.../media_0.png]`).
- Всегда выводить полученный путь в чат через markdown:
  ```markdown
  ![Описание](file:///C:/Users/.../media_0.png)
  ```
- Ниже давать ссылку на оригинальный файл в папке вывода `output/images/`.

## Запрет на самопроверку
- **Категорически запрещено** вызывать `view_file` или анализировать сгенерированные картинки без явного запроса пользователя.
