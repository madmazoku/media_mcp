# Стандарт именования артефактов и организация каталогов (Artifacts & Naming)

Документ устанавливает единый канонический регламент именования файлов, структуру каталогов хранения, жизненный цикл промежуточных данных и правила сериализации путей в `media_mcp`.

---

## 1. Канонический дефисный стандарт имён файлов

Каждый рабочий прогон (генерация изображения или видео) получает уникальный префикс выполнения исключительно через дефис (`-`):

$$\mathbf{run\_prefix} = \texttt{YYYYMMDD-HHMMSS-\{hash6\}}$$

- **`YYYYMMDD-HHMMSS`**: местное время старта задачи (например, `20261017-160530`).
- **`{hash6}`**: 6-символьный шестнадцатеричный идентификатор запуска (например, `87a49f`).
- **Все разделители в именах файлов-артефактов — строго дефисы (`-`).** Это позволяет по единому префиксу `{run_prefix}` мгновенно собрать все файлы, относящиеся к одной генерации, во всех папках (`images/`, `videos/`, `workflows/`, `temp/`, `ComfyUI/input/`).

### ⚠️ Антипаттерны именования (Категорически запрещено):
1. **Произвольные текстовые имена:** файлы вроде `hermione_biplane_5s.mp4` или `cyberpunk_neon.png` — запрещены.
2. **Включение имён сцен в имена файлов:** имена вроде `s001-bedroom_scene.png` — запрещены.
3. **Беспрефиксные или коллизионные входные файлы:** загрузка файлов в `ComfyUI/input/` под исходным именем (`anchor.png`, `mask.png`) запрещена. Любой файл, копируемый в `ComfyUI/input/`, обязан получать префикс `{run_prefix}-{role}.ext`.

## 2. Иерархия каталогов (`output_dir`)

Корневой каталог `output_dir` (задаётся в `config.json`) автоматически разворачивается в 4 изолированных подкаталога:

```
output_dir/
├── 📂 images/       # Чистовые мастер-изображения и постеры видео
├── 📂 videos/       # Чистовые смонтированные видеоролики
├── 📂 workflows/    # Зафиксированные JSON-спецификации запусков (репродуцируемость)
└── 📂 temp/         # Рабочий буфер: блоки, маски, хвосты, опорные кадры сцен
```

### Спецификация суффиксов файлов:

| Каталог | Маска имени файла | Описание содержимого |
| :--- | :--- | :--- |
| `images/` | `{run_prefix}-final.png` | Финальное сгенерированное изображение (`txt2img` / `img2img` / `inpaint` / `outpaint`). |
| `images/` | `{run_prefix}-poster.png`| Официальный постер видеоролика (опорный кадр сцены 1). |
| `videos/` | `{run_prefix}-final.mp4` | Финальный смонтированный сценарный видеоролик (FFmpeg stream copy). |
| `workflows/`| `{run_prefix}-spec.json` | Полная воспроизводимая спецификация запуска с вычисленными `seed`. |
| `temp/` | `{run_prefix}-s001-anchor.png` | Сгенерированный опорный кадр для сцены №1. |
| `temp/` | `{run_prefix}-s001-b001-end.png` | Подготовленный или сгенерированный конечный опорный кадр для сцены 1, блока 1 (`end_image`). |
| `temp/` | `{run_prefix}-s002-anchor.png` | Сгенерированный опорный кадр для сцены №2. |
| `temp/` | `{run_prefix}-norm-source.png` | Исходное изображение, масштабированное под нативное разрешение. |
| `temp/` | `{run_prefix}-crop.png`   | Исходное изображение после центрального кадрирования (`fit: "crop"`). |
| `temp/` | `{run_prefix}-outpaint-source.png`| Исходное изображение с краевым заполнением полей под дорисовку. |
| `temp/` | `{run_prefix}-outpaint-mask.png` | Автоматически сгенерированная маска полей с Gaussian Feathering. |
| `temp/` | `{run_prefix}-s001-b001-core.mp4`| Рабочий видеосегмент сцены 1, блока 1 без стыковочных кадров. |
| `temp/` | `{run_prefix}-s001-b001-tail.latent` | Сохранённый 5D латент хвоста блока 1 для префиксного чейнинга (`overlap > 0`). |
| `temp/` | `{run_prefix}-s001-b001-tail.png` | Несжатый RGB PNG последнего кадра блока 1 для 1-кадрового I2V чейнинга (`overlap == 0`). |
| `ComfyUI/input/` | `{run_prefix}-flux-src.png` / `{run_prefix}-s001-b001-input.png` | Изолированные по префиксу входные файлы для нод `LoadImage` / `LoadLatent`. |

## 3. Жизненный цикл опорных кадров (Scene Anchors vs Poster)

1. **Генерация в `temp/`:**
   - Опорный кадр каждой сцены $i$ генерируется или копируется в `temp/{run_prefix}-s{i:03d}-anchor.png`.
2. **Продвижение в постер (`poster.png`):**
   - После сборки финального ролика `videos/{run_prefix}-final.mp4` опорный кадр первой сцены автоматически копируется в чистовик:
     $$\texttt{temp/\{run\_prefix\}-s001-anchor.png} \longrightarrow \texttt{images/\{run\_prefix\}-poster.png}$$
   - Путь к нему возвращается клиенту в объекте `image` (поле `image_path`) по завершении задачи через `media_get_job`.

---

## 4. Политика сохранения временных файлов (`temp/`)

- Временные файлы в `temp/` **не удаляются автоматически** по завершении рендеринга, чтобы обеспечивать возможность отслеживания процесса генерации, поблочной диагностики и повторной сборки. Очистка временных папок выполняется независимо внешними средствами обслуживания.

---

## 5. Стандарт сериализации путей: Строго POSIX (`as_posix()`)

Во всех JSON-структурах (ответы инструментов, файлы `*-spec.json`, вывод CLI) пути **всегда** нормализуются через `Path`:
```python
Path(raw_path).resolve().as_posix()
```
Результат всегда содержит прямые слэши:
```json
"image_path": "G:/Git/Gemini/media_mcp/images/20261017-160530-87a49f-final.png"
```

## 6. Зафиксированные спецификации (`workflows/*-spec.json`)

Для каждого успешного запуска генератора в каталоге `workflows/` формируется файл `{run_prefix}-spec.json`.
Он полностью соответствует входной JSON-схеме (`schemas/requests/image_generate.json` или `schemas/scenario.json`), содержит разрешённые значения `seed` в корневых секциях (`.seed` или `.image.seed` / `.video.seed`) и может быть передан напрямую для 100% воспроизведения генерации:
```bash
bin/cli.cmd --config path/to/config.json image_generate --payload workflows/20261017-160530-87a49f-spec.json
```
